# Instruções de fluxo de trabalho de Sprint

Este arquivo é um guia obrigatório para quem for trabalhar nas sprints.
A sequência de implementação deve ser seguida com rigor para que tudo funcione perfeitamente.

## Regras principais

- Siga a ordem dos passos nos arquivos de plano de sprint.
- Não inicie o próximo passo antes de finalizar e revisar o passo atual.
- Marque cada passo com checkbox somente após a implementação e os testes estarem concluídos.
- Revise cuidadosamente as alterações antes de avançar.
- Se tiver dúvidas, pare e esclareça antes de prosseguir.
- Mantenha o `README.md` do repositório sempre atualizado quando houver mudanças relevantes de configuração, execução ou dependências.

## Onde trabalhar

- `sprints/sprint1/plan.md`
- `sprints/sprint2/plan.md`

## Como usar

1. Abra o plano da sprint correspondente.
2. Leia o passo atual e execute-o.
3. Implemente a feature.
4. Crie e execute os testes para todos os cenários possíveis.
5. Revise o código e a lógica.
6. Marque o item como concluído.
7. Só então passe para o próximo item.

## Por que isso importa

Seguir a sequência evita dependências quebradas, bugs de integração e regressões.
Cada etapa foi desenhada para garantir que a base esteja estável antes de avançar para a próxima.
